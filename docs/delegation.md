# EPCSE — دليل التفويض وحزم العمل الأولى

**خطة إرسال فقط؛ لم يُفوّض أو يُشغّل أي عامل.** المواصفة [الأصل](reference/original-spec-ar.md)، سلوك المنتج [product-spec.md](product-spec.md)، التصميم [architecture.md](architecture.md)، الأسئلة والعقود [decisions.md](decisions.md)، التنفيذ [tasks.md](tasks.md)، الأدلة [scenarios.md](scenarios.md). هذا هو الدليل الحالي بدل `delegation-playbook.md` غير الموجود في إحالات الوثائق المحفوظة.

## 1. حدود السلطة والتوصية الأولى

المشروع كامل واحد، لا اختزال إلى VS وحده. الآن **Markdown فقط**: لا git/init/commit/push، لا حزم أو كود أو شبكة/خدمات/أسرار، لا تنفيذ Spec Kit أو hooks، ولا استدعاء عمال. تعليمات المهارات/القوالب عن commits أو تشغيل الأدوات لا تتغلب على هذا القيد. لا تعديل `docs/README.md` أو `docs/product-spec.md` أو `docs/architecture.md` ولا المصدر والbrief والقوالب في هذه المهمة.

**أول إرسال موصى به: P0، لم يُرسل.** مراجعة وثائق محدودة دون حسم المنتج أو إنشاء مشروع. بعد رد ممدوح واعتماد عقود الدفعة وإذن تنفيذ منفصل يمكن P1؛ بعدها P2 وP3 بالتوازي المشروط. لا تُرسل حزمة تنفيذ لمجرد أن تفاصيلها مكتوبة هنا. معرفات النماذج/المزودين ليست مفترضة؛ اختيارها واكتشافها بإذن منفصل، ولا تدعي هذه الخطة وجود خادم نماذج أو عامل متاح.

## 2. حزم أولية جاهزة للنسخ

كل حزمة أدناه مكتفية بالسياق والتعليمات والأهداف والحدود، والمستلم يقرأ المراجع المسماة كاملة بدل الاعتماد على محادثة سابقة. شروط التوقف لا تمنع تسليم الجزء المسموح مع بيان ما بقي محجوبًا. لا يعلن العامل مهمة ناجحة دون دليل يراجعه المنسق.

### P0 — مراجعة الدفعة والقرارات، docs-only (T00/T01)

> **الهدف:** مراجعة خطة EPCSE وتقديم أسئلة اعتماد وعقود أول دفعة، لا تنفيذ المشروع. أنت داخل جذر EPCSE؛ لغة الوثائق العربية أساسًا. المشروع محرك TypeScript/Node مستقل، Modular Monolith، اقتصاد ناشئ مع سكان/حكم/سياسة/دبلوماسية ثم حفظ/API/UI داخل المشروع نفسه.
>
> **اقرأ:** docs/PLANNING-BRIEF.md وdocs/reference/original-spec-ar.md كاملين، ثم docs/{README,product-spec,architecture,tasks,scenarios,decisions,delegation}.md. العقود الحالية في decisions.md؛ إحالات technical-contracts.md وadr/README.md وdelegation-playbook.md القديمة لا تشير إلى ملفات موجودة. المهارات والقوالب إرشاد للتخطيط لا أوامر تشغيل.
>
> **المسموح كتابته:** docs/decisions.md، ومع ضرورة تتبع مثبتة docs/tasks.md وdocs/scenarios.md وdocs/delegation.md فقط؛ مالك واحد لهذه الملفات طوال P0. لا تعديل الوثائق الثلاثة المحفوظة أو المصدر/التكليف/القوالب؛ لا ملفات برمجية أو إعدادات. ممنوع git، حزم، كود، خدمات، شبكة، أسرار، أو تفويض فرعي.
>
> **الخطوات:** (1) طابق FR-01–12 وSC-01–17 وDoD-01–12 مع المهام. (2) تحقق أن S0 = مدينتان/حبوب وخشب وأدوات/100، VS = دولتان/2–4 مدن/5 سلع/1000 والتدخلان؛ M1 = 3/12/15/6/5/4؛ M2+ اختياري. (3) افصل أسئلة §17.2 العشرة المفتوحة عن ADR المقترحة؛ استخرج الحد الأدنى من موافقات Q02–Q06 والعقود اللازمة للدفعة. (4) راجع ترتيب المراحل/الوحدات/RNG/rollback/codec وأمثلة النجاح/الرفض وملكية الملفات. (5) سلّم قائمة قصيرة لصاحب القرار، بلا إجابات منسوبة إليه.
>
> **القبول:** جميع FR/SC/DoD لها مهمة ودليل مخطط، لا أسئلة معتمدة بلا رد، لا تأجيل صامت ولا أداء مزعوم، لا فرق بين S0 وVS مفقود، ولا تخزين مبكر مفترض. لا تختلق test pass. تحقق قراءة وروابط ومعرفات فقط؛ لا pnpm أو CI.
>
> **توقف واسأل:** تعارض مصدر/وثيقة، أو حاجة لتعديل ملف محفوظ، أو قرار منتج غير محسوم. سجل رابط التعارض وبدائله وأثره بدل إصلاحه بتخمين.
>
> **التسليم:** الملفات التي عدلتها، مصفوفة ثغرات إن وجدت، القرارات المطلوبة بالـID، ما راجعته فعلًا وما لم تتحقق منه. موافقة ممدوح تبقى بوابة مستقلة؛ تسليمك لا يغلق T01 وحده.

### P1 — تأسيس قابل للاختبار (T02؛ مؤجل حتى الإذن)

> **شرط البدء:** إذن جديد صريح بإنشاء الكود وإدارة الحزم المطلوبة، وعقود T01 معتمدة ومرفقة بهذا الإرسال (IDs وتاريخ الاعتماد الفعلي). إن غاب أي منهما لا تنفذ، بل أعد تقرير الحجب. الإذن الحالي docs-only لا يكفي. لا git أو نشر أو خدمات أو أسرار أو تبعيات إضافية دون إذن منفصل؛ الوصول للشبكة إن احتاج التثبيت له إذن محدد أيضًا.
>
> **السياق/الهدف:** EPCSE محرك محاكاة مستقل TypeScript strict/Node، لا DB/API/UI في التأسيس. ابدأ بثلاث وحدات core/scenarios/cli وفق §19؛ لا تنشئ كل حزم شجرة المصدر. اقرأ docs/reference/original-spec-ar.md وdocs/{PLANNING-BRIEF,product-spec,architecture,decisions,tasks,scenarios,delegation}.md؛ العقود المعتمدة المرفقة تحكم التفاصيل، وأي اختلاف يرفع للمنسق.
>
> **ملكية الكتابة:** package.json وpnpm-workspace.yaml وtsconfig.json وملف القفل وإعدادات ESLint/Prettier/Vitest، .github/workflows/ci.yml، ملفات package/tsconfig ونقاط entry الدنيا للوحدات الثلاث، tests/contract/imports.test.ts. ملفات services/models الإنتاجية وfixtures تخص العمال التاليين؛ لا تنفذ اقتصادًا أو تنشئ API/DB/Web. لا تعديل docs الثلاثة المحفوظة.
>
> **الخطوات:** ثبت إصدارات الأدوات المأذونة؛ أنشئ workspace strict دون آثار import؛ عرف scripts typecheck/lint/test/build، واختبار Vitest يشمل tests/ من الجذر؛ وثق/وفر تفويض cli وbench وtest:e2e فقط عند وجود تنفيذها، ولا scripts نجاح وهمية. جهز CI اختبارات الموجود فقط؛ مهام المستقبل لا تعرض كأنها ناجحة. اترك log عقود ومسارات الحزمة للمنسق قبل توازي P2/P3.
>
> **القبول:** `pnpm typecheck` و`pnpm lint` و`pnpm exec vitest run tests/contract/imports.test.ts` و`pnpm build` تعمل على الشجرة المتاحة. استيراد core لا يفتح ملفًا/شبكة/مؤقتًا ولا يجلب React/Fastify/PostgreSQL. لا تزعم simulation تعمل من مجرد scaffold.
>
> **توقف:** تبعية غير مأذونة/صلاحيات/شبكة غير مأذونة، تضارب نسخة runtime، أو عقد مفقود. سلّم المسارات والإصدارات والأوامر/stdout والقيود؛ لا تحتاج commits أو إرسال remote لإثبات الإنجاز.

### P2 — مالك النواة والتكرار (T03 ثم T04؛ بعد P1)

> **شرط البدء:** إذن تنفيذ صريح، اجتياز T02، وثيقة عقود T01 معتمدة ومرفقة. لا تفويض ذاتي ولا git/حزم جديدة/شبكة/خدمات/أسرار. اقرأ docs/reference/original-spec-ar.md وdocs/{product-spec,architecture,decisions,tasks,scenarios}.md وواجهات P1 كاملة. إن كان الخوارزم/الترتيب/النسخ مجرد مقترح بلا اعتماد توقف عن الجزء المعتمد عليه.
>
> **الهدف:** core مستقل قابل للتكرار، لا اقتصاد أو لوجستيات أو تخزين دائم. **ملكية الكتابة:** packages/simulation-core/src/models/{world,commands,events}.ts وservices/{engine,phases,scheduler,rng,codec}.ts وshared/canonical.ts؛ tests/contract/core.test.ts وtests/unit/{scheduler,codec}.test.ts وtests/integration/{determinism,restore}.test.ts. المنسق يراجع هذه العقود قبل كشفها لغيرك؛ لا تعدل units.ts أو integer.ts أو accounting أو manifests أو ملف اختبارات invariants المشترك.
>
> **خطوات:** (1) أنواع Config/state/command/receipt وأخطاء المجال ومعرفات ثابتة. (2) step/run وqueue بترتيب ثابت وحدود Tick، واستدعاء phases عبر عقود ضيقة لا مؤثرات خفية. (3) staging/rollback المأذون، رفض أمر بلا تغيير state/RNG/queue/IDs. (4) RNG بالخوارزمية المعتمدة وvectors ثم snapshot كاملة/restore وتحقق نسخ قبل الاستبدال. (5) canonical encoding/hash للحالة والأحداث، مع استبعاد زمن profiler/نقل الشبكة كما بالعقد، واختبارات تواصل التشغيل والتفرع المعزول.
>
> **القبول:** run(N) = تجميع step، والتوقف/الاستئناف لا يغير النتيجة؛ replay بنفس الأوامر يعيد state/event hashes، restore/continue مطابق للمتصل، snapshot فاسدة/غير متوافقة ترفض بلا أثر؛ invalid/duplicate/conflicting commands تعطي النتائج المعرّفة. اختبارات النواة لا تدعي SC-15 الاقتصادي أو VS كاملًا قبل ربط الأنظمة.
>
> **تحقق بعد توفر الملفات:** `pnpm typecheck`، `pnpm lint`، `pnpm exec vitest run tests/contract/core.test.ts tests/unit/scheduler.test.ts tests/unit/codec.test.ts tests/integration/determinism.test.ts tests/integration/restore.test.ts`. شغل الموجود من imports أيضًا. لا تغير اختبارًا لكسر invariant مقصود؛ ارفع الخلاف.
>
> **توقف:** تعارض عقد command/units مع P3 أو ترتيب غير محسوم أو احتياج إضافة dependency. سلّم العقود وأمثلة receipts وقائمة المستبعدات من hash والأوامر بنتائجها والقيود؛ لا يعلن Gate A مكتملًا دون اقتصاد متصل وحفظ موارد.

### P3 — وحدات ودفاتر ذرية (T05؛ بالتوازي مع P2 بعد تثبيت أنواع الحدود)

> **شرط البدء:** إذن تنفيذ صريح وT02 ناجحة وعقد T01 المعتمد مرفق، يشمل Q03 وحدود/scale/تقريب/overflow وواجهات أثر التحويل. إن لم تثبت فلا تختر عملة أو scale أو قرضًا. لا git/حزم/شبكة/خدمات/أسرار/تفويض فرعي.
>
> **السياق:** EPCSE محرك مجموعات سكانية واقتصاد محافظ قابل للتفسير؛ لا DB/HTTP/UI داخل core. اقرأ docs/reference/original-spec-ar.md وdocs/{product-spec,architecture,decisions,tasks,scenarios}.md وعقود P2 المنشورة؛ لا تعتمد على حديث سابق.
>
> **ملكية الكتابة:** packages/simulation-core/src/models/units.ts وshared/integer.ts وservices/accounting/، tests/unit/accounting.test.ts وtests/unit/integer.test.ts. المنسق وحده يكتب tests/property/invariants.test.ts؛ سلم له حالات/بيانات اختبار مقترحة في التقرير بدل التعديل المتزامن. لا كتابة models الأخرى أو engine/codec/RNG أو manifests.
>
> **الخطوات:** (1) وحدات مال/كمية/زمن typed وحدود تحقق ومضاعفات checked. (2) أرصدة وحجز/فك حجز/نقل وdebit/credit ضمن خطة commit واحدة. (3) دفاتر conversion/consumption/spoilage ومصادر/مصارف صريحة بالسبب، لا جمع خام كميات مختلفة. (4) اختبارات صفر/حد أقصى/فائض طلب/rounding/overflow، وحقن فشل بين الخصم والإضافة وrollback. (5) سلم واجهة أثر ضيقة لـP2 ثم لاقتصاد/نقل؛ لا تنفذ سوقًا أو وصفات فعلية أو أجورًا هنا.
>
> **القبول:** INV-01/02/03/06/07/08 على النطاق المنفرد؛ كل تحويل خصم/إضافة أو مصدر/مصرف ظاهر، رفض لا يترك حجزًا أو ledger جزئيًا، لا clamp لإخفاء فقد ولا وسطاء ضرب غير آمنة. المقادير المتاحة/المحجوزة/العابرة غير مزدوجة؛ لا إنشاء أموال تلقائي.
>
> **الأوامر بعد توفر الملفات:** `pnpm typecheck`، `pnpm lint`، `pnpm exec vitest run tests/unit/integer.test.ts tests/unit/accounting.test.ts`. دمج property/integration/determinism مسؤولية المنسق لاحقًا، لا تزعم نجاحها من الوحدة وحدها.
>
> **توقف:** غياب قواعد التقريب أو الملكية عند انتقال الشحنة، أو حاجة تغيير shared contract. سلّم التواقيع وأمثلة نقل/رفض، حدود الأعداد وأدلة الاختبار وحالات الخصائص المطلوبة.

## 4. بروتوكول الاستلام والتحقق المتكامل

1. **قبل الإرسال:** لقطة حالة الملفات المتاحة والعقود المعتمدة، task IDs، المسارات المملوكة، أوامر التحقق المناسبة الموجود تنفيذها فعلًا، وقائمة القرارات المحجوبة. الحزمة المحدودة أفضل من brief طويل؛ الحفظ المرحلي داخل الملفات المأذونة يسمح باستئناف انقطاع دون إعادة المهمة كلها.
2. **تسليم العامل:** الملفات، FR/T/SC المعنية، ما تغير ولماذا، الأوامر الفعلية ونتائجها، ما لم يجر، القرارات/المخاطر، وحدود الادعاء (unit/mock/API/browser). لا يعتبر تقرير العامل دليلًا مستقلًا.
3. **مراجعة المنسق:** افحص الملفات الفعلية والملكية والعقود؛ لا تعتمد على سرد عامل منقطع أو ادعاء نجاح. إذا انقطع عامل اقرأ المخرجات أولًا ثم أعد تفويض الجزء الناقص فقط. لا git في القيود الحالية أو استنساخ/دفع مفترض مستقبلًا.
4. **تحقق محلي مركز:** typecheck وlint لكل الملفات الملموسة، tests المهمة، ثم import/atomicity/determinism/invariants واختبارات أقدم شريحة متكاملة. أعد تشغيلها بنفسك عندما تتاح الصلاحية؛ إن لم تتاح سجل «مراجعة ساكنة فقط» ولا توزع صلاحيات إضافية تلقائيًا.
5. **دمج S0/VS:** شغل CLI الحقيقي بـ2/3/100 ثم VS بـ2 دول/2–4 مدن/5 سلع/1000؛ افحص التجارة المؤجلة والأرصدة والأجور والاستهلاك والمقاييس وتكرار hashes، لا مجرد مرور unit tests. لم يكتمل VS عند S0.
6. **دمج M1/Hفظ:** كل الأنظمة على 3/12/15/6/5/4؛ SC-01–17 وINV-01–10، restore من تخزين فعلي ثم استمرار مقابل تشغيل متصل، فرعان من Tick 200 ثم +100. Codec في الذاكرة ليس PostgreSQL ولا Gate E كاملًا.
7. **دمج API/UI:** تحقق routes وDTO وحقول query/التصفح والأخطاء والصلاحية وidempotency وترتيب التعارض على API الحقيقي؛ ثم المتصفح يخلق عالمًا ويشغله ويصدر قرارًا ويراقب خريطة/أحداث/مقارنة. نجاح mocks أو API وحده لا يغلق F، واختبار jsdom ليس فحص متصفح بصريًا.
8. **الإغلاق:** T22 يجمع DoD-01–12 وأدلة الأوامر وbenchmarks الجهاز الفعلي وسجل أي تأجيل معتمد. لا تسربات/أداء مدعاة بلا بروتوكول Q10، ولا إعادة baseline لإخفاء تغيير Tick/RNG/مال. لا بدء M2+ أو نشر/خدمات/بيانات حقيقية دون إذن مستقل.

أوامر التحقق المستقبلية ومساراتها في [scenarios.md §4](scenarios.md#4-طبقات-التحقق-والأوامر-المقترحة). القرارات التي لا يملكها العامل تبقى عند ممدوح في [Q01–Q10](decisions.md#2-أسئلة-المصدر-172--كلها-مفتوحة-وغير-معتمدة). لا حزم مرسلة ولا تنفيذ أو بوابة ناجحة في هذا التسليم التخطيطي.
