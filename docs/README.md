# EPCSE — فهرس التخطيط وحالة المشروع

**الحالة: مسودة للمراجعة، غير معتمدة للتنفيذ.** المشروع كله وحدة واحدة؛ VS وM1 تسميات إتاحة من المرجع وليستا منتجين مستقلين. جميع المهام والاختبارات والملفات البرمجية والأوامر الواردة هنا **مخططة وليست موجودة أو ناجحة**. لم تُقَس سرعة أو ذاكرة ولم يُنجز أي بند DoD بهذه الوثائق.

## السلطة وحدود العمل

1. [التكليف](PLANNING-BRIEF.md) يحكم هذه الجلسة: Markdown فقط، بلا تنفيذ أو git أو تثبيت أو خدمات أو شبكة أو أسرار أو تفويض فعلي.
2. [المواصفة الأصلية كاملة](reference/original-spec-ar.md)، الإصدار 0.1، مصدر نطاق المشروع. تاريخها النصي بيانات مرجعية لا إثبات إنجاز.
3. الوثائق أدناه صياغة تخطيطية؛ التعارض يُرفع لممدوح ولا يُحل باختراع قرار منتج.
4. استُخدمت مهارتا `spec-driven-development` و`code-refactorer` صراحة: فصل ماذا/كيف/التحقق، حزم تفويض محدودة، مسؤولية الحالة واتجاه التبعيات وعزل I/O. لا يوجد كود لإعادة هيكلته؛ لا ادعاء refactor ولا اتباع تعليمات commit غير المناسبة للتكليف.
5. قوالب [spec](spec-kit-templates/spec-template.md) و[plan](spec-kit-templates/plan-template.md) و[tasks](spec-kit-templates/tasks-template.md) إرشاد هيكلي فقط. لا تثبيت Spec Kit أو تشغيل أوامر/سكربتات/خطافات، ولا إنشاء دستور أو فرع أو شجرة مواصفات موازية. الاختبارات إلزامية هنا بحكم المرجع، لا اختيارية كما في المثال القالبي.

## حالة البوابات

| البوابة | النتيجة المطلوبة | الحالة الآن |
|---|---|---|
| R | اعتماد نطاق المسودة والعقود اللازمة للدفعة بواسطة ممدوح | مفتوحة؛ الكتابة لا تعني الموافقة |
| S0 / A–C مصغرة | §19: مدينتان، حبوب/خشب/أدوات، 100 Tick، CLI وتوازن وتكرار ومسار تجارة | غير منفذة؛ ليست قبول VS |
| VS / A–D مبسطة | §3.1 كاملًا: دولتان، 2–4 مدن، 5 سلع، 1000 Tick، اقتصاد/تجارة/سكان/حكومات وتدخلان | غير منفذة |
| E | snapshot/restore ومقارنة من أساس واحد | غير منفذة؛ عقد مبكر في الذاكرة، تخزين دائم لاحق |
| M1 / A–F وDoD | كل متطلبات M1 والواجهة والتحقق والتوثيق والقياس | غير منفذة |
| M2+ | بحث اختياري، لا شرط لـM1 ولا بدء تلقائي | غير مأذون |

بوابات A–F من §13.1 نقاط تحقق متراكمة، لا تصريح بإسقاط ما بعدها. لا نعيد وعود الأسابيع/الأشهر في §13: التسلسل بالتبعيات والأدلة فقط. §19 شريحة تأسيس داخل المشروع، لا بديل عن أرقام VS. اختبار snapshot المبكر لا يعني PostgreSQL مبكرًا ولا اكتمال Gate E.

## ما يحتاج صاحب المشروع

- مراجعة تفاصيل التنفيذ المفتوحة في [القرارات](decisions.md)؛ التوجيهات المعتمدة في [رؤية المملكة](kingdom-vision.md) لا تحسم السياسات والحالات الطرفية غير المحددة.
- الموافقة على العقود والملكية قبل تشغيل عمال التنفيذ؛ اختيار النموذج/المزود بعد اكتشاف معرفاته الفعلية بإذن منفصل.
- عدم تأجيل سيناريو من M1 بصمت؛ الاستثناء الموثق في DoD الأصلي محفوظ، مع سبب ونطاق بديل ومالك وموافقة واضحة.

**أول إرسال موصى به، غير مُرسل:** الحزمة P0 في [دليل التفويض](delegation.md) لمراجعة القرارات والعقود وتثبيت الدفعة، وليس إنشاء المشروع. المخاطر وعدم اليقين موثقة في ADR، وأدلة التنفيذ ستُسجَّل لاحقًا دون تحويل مخطط الاختبارات إلى نتائج نجاح.
