# وثيقة مواصفات مشروع محرك المحاكاة الاقتصادية والسياسية والحضارية

> **اسم العمل:** Economic, Political & Civilization Simulation Engine (EPCSE)  
> **نوع الوثيقة:** Product Requirements + System Design + Scenario Catalogue  
> **الإصدار:** 0.1 — مسودة تأسيسية قابلة للتحديث  
> **التاريخ:** 13 نوفمبر 2026  
> **اللغة الأساسية للمشروع:** TypeScript  
> **حالة المشروع:** التخطيط والتحليل — لم يبدأ التنفيذ بعد

---

## 1. الملخص التنفيذي

الهدف بناء **محرك محاكاة مستقل** لعالم يتكون من دول وحضارات ومدن وأسواق وسكان ومؤسسات؛ تُحاكى فيه العلاقات الاقتصادية والسياسية والدبلوماسية عبر قواعد قابلة للاختبار، لا عبر نصوص أحداث معدّة مسبقًا. تتيح الواجهة لاحقًا مراقبة العالم والتحكم في متغيراته، لكن **المحرك يجب أن يعمل دون واجهة أو خادم ويب**.

**التوجه المعتمد:** محاكاة اقتصادية واقعية نسبيًا بوصفها العمود الفقري، مع مدن وحضارات وحكومات وسياسة داخلية ودبلوماسية واحتجاجات وإضرابات. ليس الهدف في المرحلة الأولى إنشاء لعبة استراتيجية قابلة للبيع، بل مشروع هندسة برمجيات متقدم يمكن أن يستند إليه منتج أو لعبة لاحقًا.

### 1.1 النتائج المنشودة

1. تشغيل عوالم قابلة للتكرار من نفس الإعدادات والبذرة العشوائية (seed).
2. إنتاج سلوك ناشئ (Emergent Behavior) مثل نقص الغذاء أو الهجرة أو الإضرابات أو الاتفاقيات التجارية **نتيجة تفاعل القواعد**، لا بكتابة النتائج مسبقًا.
3. فصل منطق المحاكاة عن التخزين والاتصال والخرائط والواجهة.
4. تتبّع أسباب التغيرات الاقتصادية والسياسية عبر سجلات وأحداث ومقاييس.
5. دعم سيناريوهات «ماذا لو؟» ومقارنة نتائج سياسات مختلفة من حالة ابتدائية واحدة.
6. إتاحة توسيع العالم تدريجيًا إلى عدد أكبر من المدن والكيانات دون إعادة كتابة النواة.

### 1.2 ما ليس هدفًا في البداية

- محرك رسوميات ثلاثية الأبعاد أو منافسة Unity / Unreal.
- محاكاة كل إنسان كوحدة منفردة؛ تُستخدم **مجموعات سكانية** لتقليل تكلفة الحساب.
- نموذج علمي يتنبأ باقتصادات الدول الواقعية بدقة؛ النتائج تجريبية وتعتمد على الفرضيات.
- أنظمة قتالية تفصيلية أو خرائط تكتيكية أو ذكاء عسكري.
- حسابات اقتصادية تعتمد على LLM عند كل دورة زمنية.
- Microservices أو بنية موزعة من اليوم الأول.

## 2. مبادئ التصميم غير القابلة للتنازل

| المبدأ | القاعدة العملية |
|---|---|
| Engine First | يمكن استيراد وتشغيل `simulation-core` دون React أو Fastify أو PostgreSQL |
| Determinism | نفس الإصدار + الإعدادات + seed + تسلسل الأوامر = نفس نتائج المحاكاة |
| Explicit Time | الزمن الافتراضي منظّم في Ticks، وليس معتمدًا على ساعة النظام |
| Conservation | لا تظهر بضائع أو أموال أو سكان من العدم؛ أي خلق/فقد يجب أن يكون معللًا بقواعد صريحة |
| Observable | تتوفر مقاييس وسجلات تبيّن **لماذا** تغير مخزون أو سعر أو رضا أو علاقة |
| Modular | كل نظام له واجهات وعقود واضحة، ولا يغيّر حالة الأنظمة الأخرى خفية |
| Testable | تستدعي اختبارات الوحدة والمحاكاة المحرك دون API أو قاعدة بيانات |
| Scalable by Design | المجموعات والدفعات والعمليات المجمّعة هي الافتراضي؛ لا نعتمد على عشرات آلاف الوعود async |
| Configurable | وصف الموارد والوصفات والسياسات وقواعد العالم موجود في بيانات محددة النسخ |
| Explainable AI | قرارات الوكلاء قابلة للتفسير ومُسجَّلة، ولا تشترط خدمة LLM خارجية |

**تنبيه معماري:** كلمة *Enterprise* هنا تصف مستوى التنظيم والانضباط الهندسي، لا تستدعي تعقيدًا مصطنعًا مثل Kubernetes أو عشرات الخدمات.

## 3. نطاق الإصدار ومراحل الإتاحة

### 3.1 Vertical Slice — أول نموذج قابل للتشغيل (VS)

نموذج صغير لكنه مكتمل المسار، الغرض منه اختبار الفكرة هندسيًا:

- دولتان، مدينتان إلى أربع مدن.
- خمسة موارد/سلع أساسية.
- إنتاج واستهلاك ومخزون وأسعار محلية.
- طريق تجارة واحد على الأقل، وتكلفة نقل وزمن تسليم.
- مجموعتان سكانيتان على الأقل؛ حكومة واحدة لكل دولة.
- إجراء حكومي اقتصادي واحد (ضريبة أو دعم) وقرار دبلوماسي تجاري واحد.
- تشغيل 1000 Tick من سطر الأوامر مع نتائج قابلة للتكرار.
- دون واجهة خرائط، ودون حساب كل فروع السياسة المعقدة.

### 3.2 النسخة المتقدمة الأولى (M1)

**أهداف السعة التصميمية، لا بيانات تاريخية ولا ادعاءات أداء مقاسة:**

| العنصر | النطاق المستهدف |
|---|---:|
| الدول/الحضارات | 3 |
| المدن | 12 (مثال: 4 لكل دولة) |
| أصناف السلع والموارد | 15 |
| القطاعات الاقتصادية | 6 |
| الفئات السكانية الاقتصادية | 5 |
| الأشكال الحكومية المدعومة كقواعد أولية | 4 |
| محاور التفاعل | اقتصاد، إنتاج، سكان، لوجستيات، مدن، سياسة، دبلوماسية |

### 3.3 ما بعد M1 (M2+)

بحث وتطوير، نقود وبنوك وديون أكثر تعقيدًا، انتخابات تفصيلية، أحزاب متعددة، أزمات مصرفية، نزاعات مسلحة على مستوى استراتيجي، اتفاقيات متعددة الأطراف، تعديل القوانين المتقدم، مدن أكثر، وتوزيع الحساب على خيوط متعددة. كلها **خيارات توسعة** وليست شروطًا للنسخة الأولى.

## 4. تعريف العالم والكيانات الأساسية

### 4.1 التسلسل العام

`World -> Civilization/Nation -> City -> District (لاحقًا)`

يرتبط بكل مدينة سوق ومخازن ومجموعات سكانية ومؤسسات إنتاجية ومرافق نقل. قد ترتبط المدن عبر شبكة طرق ونقاط عبور؛ وترتبط الدول بعلاقات دبلوماسية واتفاقيات تجارية.

### 4.2 الكيانات المقترحة

| الكيان | أقل معلومات مهمة |
|---|---|
| World | id، seed، نسخة القواعد، tick الحالي، الإعدادات |
| Nation | id، الاسم، المدن، الحكومة، الخزينة، سياسات التجارة والضرائب |
| Civilization | id، السمات الثقافية والتقنية، الارتباط بالدول؛ يمكن دمجها مؤقتًا مع Nation |
| City | id، الدولة، الموقع المنطقي، السكان، البنية التحتية، السوق، المخازن |
| Commodity | id، الوحدة، الصنف، قابلية التلف، القيم الأساسية |
| Inventory | المدينة/الجهة المالكة، السلعة، الكمية المحجوزة والمتاحة |
| Producer | القطاع، وصفة الإنتاج، العمالة، الطاقة، المدخلات والمخرجات |
| PopulationCohort | الحجم، الدخل، المهنة/المهارات، الحاجات، الرضا، الميل للهجرة |
| Market | المدينة، عروض البيع والشراء، أسعار مرجعية، صفقات تمّت |
| TradeRoute | المصدر والوجهة، السعة، المدة، التكلفة، مخاطر التأخير |
| Shipment | البضاعة، الكمية، المالك، نقطة المغادرة والوصول، tick الوصول |
| Government | الشكل، الصلاحيات، الثقة، القدرة الإدارية، الموارد المالية |
| Policy | النوع، القيم، شروط السريان، تاريخ البدء والانتهاء |
| PoliticalGroup | الفئة الممثلة، الأهداف، التنظيم، حجم التأييد، الموارد |
| SocialAction | احتجاج/إضراب، القطاع/المدينة، المشاركون، المطالب، الحالة |
| DiplomaticRelation | الدولتان، الثقة، المصالح، القيود، الالتزامات |
| Treaty | الأطراف، البنود، مدة السريان، عقوبات المخالفة، حالة التنفيذ |
| SimEvent | النوع، tick، المصدر، الأسباب، الآثار، المعرّفات المرتبطة |

**قواعد تعريف:** جميع المعرّفات ثابتة؛ لا نستخدم أسماء الدول أو المدن كمفاتيح. معايير القياس ووحدات الموارد موحّدة. لا يسمح بتعديل حالة العالم مباشرة من واجهة React.

### 4.3 سلع أولية مقترحة لـ M1 (15)

1. حبوب، 2. خضراوات، 3. ماشية، 4. خشب، 5. حجر، 6. خام حديد، 7. فحم، 8. حديد مصنّع، 9. أدوات، 10. نسيج، 11. ملابس، 12. خبز/غذاء معالج، 13. مواد بناء، 14. أدوية، 15. آلات.

هي **قائمة بيانات قابلة للاستبدال** وليست حسمًا لفترة تاريخية معينة. لاحقًا يمكن إنشاء سيناريوات بفترات زمنية وتقنيات مختلفة دون تغيير محرك الحساب نفسه.

### 4.4 القطاعات الستة المقترحة

الزراعة، التعدين/الاستخراج، الصناعة، تصنيع الأغذية، الإنشاءات، النقل والخدمات اللوجستية. كل قطاع قد يحتوي أنواعًا من المنتجين ووصفات مختلفة.

### 4.5 الفئات السكانية الخمس المقترحة

سكان ريفيون منخفضو الدخل، سكان حضريون منخفضو الدخل، فئة متوسطة الدخل، مالكو الأعمال/رأس المال، عاملون في القطاع العام. **الفئة الاقتصادية ليست بالضرورة المهنة**؛ تحفظ المهارات والتوظيف في حقول منفصلة حتى لا يختلط التصنيف الاجتماعي بتقسيم سوق العمل.

### 4.6 أشكال حكومية قابلة للتكوين

مجلس مدن/تجمع مدني، ملكية، نظام برلماني، جمهورية مركزية. الاختلاف الأولي لا يكون بالاسم فقط: لكل شكل قواعد في اتخاذ القرار، الاعتراض، الشرعية، ومدة تنفيذ السياسات. **لا نفترض أي ترتيب معياري أو «أفضلية» سياسية بين الأشكال.**

## 5. نواة المحاكاة (Simulation Core)

### 5.1 الزمن والدورات

- التعيين الابتدائي: `1 tick = يوم واحد افتراضي`.
- قرارات ذات دورات مختلفة: أسعار واستهلاك يومية، موازنات شهرية، سياسات وخطط ممتدة، انتخابات عند تحقق جداولها المعرّفة.
- قيمة `speed` تغيّر سرعة تشغيل الـTicks على الشاشة، لا القواعد الحسابية لكل Tick.
- الأوامر الخارجية تُستلم عند حدود الدورة، وتُؤرشف بترتيب ثابت.
- كل نظام يستهلك RNG منشأ من Seed بنظام واضح لتجنب نتائج مختلفة بسبب تغيّر ترتيب التنفيذ.

### 5.2 ترتيب مقترح لمراحل Tick

1. التحقق من الأوامر المعلّقة والسياسات التي بدأ سريانها والأحداث المجدولة.
2. تطبيق مؤثرات الطبيعة وحالة البنية التحتية واستلام الشحنات المستحقة.
3. تخصيص العمالة وتحديد القدرة الإنتاجية.
4. الإنتاج وتسجيل استهلاك المدخلات وإضافة المخرجات والأجور.
5. مطابقة عروض الأسواق المحلية وتحديث الأسعار وفق قواعد محددة.
6. شراء واستهلاك السلع وتحصيل الرسوم والضرائب وتسوية الحسابات.
7. تحديث الرفاه والرضا والبطالة والهجرة والتحركات الاجتماعية.
8. فحص قرارات الحكومة والسياسات والعلاقات الدبلوماسية الدورية.
9. جدولة الشحنات الجديدة ومسارات التجارة وتكاليفها.
10. تحديث المقاييس ونشر الأحداث والتحقق من Invariants وأخذ Snapshot عند اللزوم.

ترتيب المراحل **قرار تصميم أولي**؛ قد يتغير وفق اختبارات الاتساق، لكن يجب أن يكون موثقًا وحتميًا. مثال: السلع الواردة في بداية الدورة تكون متاحة في سوقها خلال الدورة نفسها، أما الشحنات المغادرة فتصل في Tick لاحق.

### 5.3 واجهة برمجية مبدئية للمحرك

```ts
interface SimulationConfig {
  worldSeed: number;
  tickDurationDays: 1;
  rulesVersion: string;
}

interface SimulationEngine {
  getState(): Readonly<WorldState>;
  submit(command: SimulationCommand): CommandReceipt;
  step(): TickResult;
  run(ticks: number): SimulationRunResult;
  snapshot(): WorldSnapshot;
  restore(snapshot: WorldSnapshot): void;
}
```

هذه **واجهة تصورية** وليست عقدًا نهائيًا يُنفّذ حرفيًا. قد تعاد هيكلتها لتقليل نسخ حالة العالم المكلف واستخدام selectors بدل `getState()` الكاملة في العوالم الضخمة.

### 5.4 أسلوب المحاكاة

- **Discrete-Time Simulation** للنشاط الاقتصادي الدوري.
- **Discrete-Event Scheduling** للمفاوضات والانتخابات وتأخر الشحنات والكوارث.
- **Agent-Based Modeling** لمجموعات التجار والشركات والحكومات والجهات الاجتماعية، دون تجسيد كل فرد بالضرورة.
- **Graph Algorithms** لمسارات المدن وحساب الزمن والتكلفة والسعة والقيود الحدودية.
- **State Machines** لحالات الاتفاقيات والإضرابات والتفاوض، مع قواعد انتقال واضحة.

## 6. المتطلبات الوظيفية المفصلة

### FR-01 — إنشاء العالم والتحكم به

- إنشاء عالم من Config وSeed دون الوصول إلى قاعدة بيانات.
- دعم بدء/إيقاف/استئناف/تقدم بعدد محدد من الـTicks.
- تحميل سيناريو مهيأ مسبقًا وإنشاء عالم جديد مع تحقق شامل من المدخلات.
- استخراج تقرير لحالة العالم والتغيرات في فترة زمنية.
- الاحتفاظ برقم نسخة القواعد لمنع قراءة Snapshot قديمة بطريقة خاطئة.

**قبول مبدئي:** تشغيل 1000 Tick بذات Config/Seed/Commands يعطي نفس بصمة الحالة النهائية على نفس إصدار المحرك.

### FR-02 — الموارد والمخزون

- تتبع الكميات المتاحة والمحجوزة والتالفة لكل مالك/مدينة/سلعة.
- منع الكميات السالبة أو نقل كمية أكبر من الرصيد المتاح.
- تنفيذ التحويلات بين المخزون والمنتج والسوق والشحنات بصورة ذرية داخل Tick.
- تعريف تلف بعض السلع أو خسارتها بواسطة قواعد صريحة قابلة للتعطيل.

**قبول مبدئي:** لا تكون أي قيمة مخزون سالبة بعد كل Tick؛ ويكون كل تغيير قابلًا للتتبع.

### FR-03 — الإنتاج وسوق العمل

- المنتج يستهلك مدخلات وفق Recipe، ويستخدم عمالة وطاقة/قدرة ومعدات.
- حجم الإنتاج محدود بأصغر قيد من المدخلات والعمالة والطاقة والاستيعاب.
- دفع الأجور وتسجيل نفقات المنشآت وإيراداتها.
- تحديث البطالة والقدرة الشرائية عندما تغلق منشآت أو تتوسع.

### FR-04 — السكان والاستهلاك

- الاحتياجات الأساسية تختلف بحسب الفئة والسعر والدخل والموقع.
- شراء السلع وفق ميزانية محدودة مع تمييز الضروري عن الاختياري.
- تسجيل عدم تلبية الاحتياجات وتأثيره التراكمي في الرفاه والرضا.
- دعم الهجرة بين المدن وفق فرص العمل والأجور وتكلفة الانتقال والاستقرار.
- الولادات والوفيات والتوسع السكاني يمكن تبسيطها أولًا، ثم ضبطها لاحقًا.

### FR-05 — الأسواق والأسعار

- سوق محلي لكل مدينة مع أسعار مرجعية أو عروض بيع/شراء.
- قوى العرض والطلب والنقل/الضرائب تؤثر في السعر؛ لا توجد زيادات عشوائية بلا سبب.
- تحديد حدود معقولة لتغير الأسعار في Tick واحد لتجنّب عدم الاستقرار العددي غير المقصود.
- تتبع صفقات فعلية وكميات غير مباعة واحتياجات لم تُلبّ.
- معالجة غياب السيولة أو غياب السلعة دون قسمة على صفر أو NaN.

### FR-06 — اللوجستيات والتجارة

- تعريف شبكة طرق متصلة أو منفصلة، مع زمن نقل وتكلفة وسعة.
- إنشاء شحنة مع حجز المخزون والقدرة على المسار وحساب Tick وصولها.
- فرض رسوم جمركية أو عقوبات أو إغلاق حدود وفق السياسة والعلاقات الدبلوماسية.
- الشحنات أثناء الطريق لا تكون ضمن المخزون المتاح في مدينة الانطلاق أو الوصول.
- دعم إعادة التوجيه/الإلغاء وفق قواعد محددة لاحقًا.

### FR-07 — المدن والبنية التحتية

- كل مدينة تمتلك سكانًا وأسواقًا وبنى إنتاجية ومرافق ونقلًا.
- نمو المدينة مرتبط بالوظائف والإنتاج وتوفر الخدمات والهجرة، لا بقيمة نمو ثابتة فقط.
- استثمارات الحكومة أو الشركات يمكن أن تؤثر في سعة المخازن والطرق والإنتاج.
- العوائق اللوجستية قد تفصل المدن اقتصاديًا وإن كانت في الدولة نفسها.

### FR-08 — الحكومة والسياسات العامة

- خزينة وإيرادات ضريبية ومصروفات عامة مسجلة بصورة محاسبية مبسطة.
- سياسات قابلة للتكوين: ضرائب، دعم، رسوم جمركية، استثمار بنى تحتية، قيود تجارة.
- للسياسات تاريخ بدء وتأخر تنفيذ وتكاليف وآثار واضحة.
- القرارات تتأثر بالميزانية والثقة والأهداف والمؤسسات والنظام الحكومي.
- عجز الخزينة لا يُحل بإضافة أموال تلقائيًا؛ الاقتراض/الإصدار النقدي آليات منفصلة إن فُعّلت.

### FR-09 — السياسة الداخلية والإضرابات

- مؤشرات: رضا السكان، البطالة، الأجور الحقيقية، تكلفة المعيشة، الثقة بالحكومة، مستوى التنظيم.
- جماعات سياسية/مهنية يمكن أن تقدّم مطالب وطلبات تغيير سياسة.
- الإضراب حدث اجتماعي ناتج عن مجموعة عوامل وشروط تنظيم، **وليس** نتيجة حتمية لارتفاع السعر وحده.
- تأثير الإضراب يظهر في القدرة الإنتاجية والدخل والضرائب وسلاسل الإمداد.
- تفاوض يستند إلى مطالب وتنازلات وتكلفة استمرار الإضراب وقدرة الحكومة/المنشآت.
- دعم حالات: `proposed -> active -> negotiating -> resolved | failed | expired` مع توثيق الانتقالات.
- تجنّب استخدام قيم سياسية أخلاقية مبسطة مثل «النظام X أفضل تلقائيًا»؛ تحكم النتائج المعايير المعرّفة.

### FR-10 — الدبلوماسية

- علاقات ثنائية تتأثر بالتبادل التجاري والالتزامات والقرارات الحكومية والأحداث.
- اتفاقيات تجارة تتضمن الرسوم والحصص والمدة وشروط الانسحاب.
- إغلاق معبر أو فرض عقوبات يؤثر في الطرق والأسعار والميزانيات والرضا الداخلي.
- قرارات الحكومات مستقلة وفق مصالحها ومحدودياتها؛ لا تُجبر دولة على توقيع اتفاق من أجل إكمال سيناريو.
- خصومات أو نزاعات سياسية قد تبقى غير عسكرية في M1.

### FR-11 — قرارات الوكلاء (Agents)

- وكلاء للشركات/المنتجين/التجار/الحكومات/الجماعات الاجتماعية.
- تنفيذ Utility Scoring أو قواعد قرار شفافة قابلة للاختبار.
- كل قرار يحتوي: الخيارات، المعلومات المتاحة، القيود، سبب القرار، النتيجة.
- عدم افتراض اطلاع كل وكيل على حالة العالم بالكامل؛ يمكن إضافة معلومات ناقصة وتأخر معلومات لاحقًا.
- الذكاء الاصطناعي اللغوي اختياري للشرح/التقارير، وليس عنصرًا لازمًا لصحة الدورة.

### FR-12 — مراقبة العالم والتحليل

- مقاييس: الإنتاج، أسعار السلع، المخزون، الاستهلاك غير المشبع، الأجور، البطالة، التجارة، خزينة الدولة، الرضا، الإضرابات، الاتفاقيات.
- استعراض سلسلة زمنية للمقاييس على مستوى مدينة أو دولة أو عالم.
- سجل أحداث يمكن التصفية فيه حسب النوع والكيان والفترة.
- مقارنة تشغيل سيناريوين لهما نقطة انطلاق واحدة وتدخلات مختلفة.

## 7. صيغ الحساب الأولية والضوابط

> هذه أمثلة لإرساء التوقعات، **وليست نظرية اقتصادية نهائية**؛ تُوثق كل صيغة وتختبر وتُعايَر قبل اعتمادها.

### 7.1 الإنتاج

`output = min(inputCapacity, laborCapacity, equipmentCapacity, infrastructureCapacity) × productivityModifier`

يتوقف الإنتاج عند نقص أي مدخل إلزامي. لا تُنشأ مخرجات قبل خصم المدخلات اللازمة، ويتم التعامل مع الكسور بوحدات قياس مضبوطة.

### 7.2 الأسعار

يُقترح في النسخة الأولية تحديث سعر مرجعي تدريجي وفق فجوة الطلب/العرض المرصودة ضمن نطاق يومي محدود؛ أو اعتماد مطابقة أوامر سوق. **يجب اختيار آلية واضحة واحدة لكل نوع سوق عند التنفيذ** حتى لا يحسب السعر مرتين.

### 7.3 الرضا والضغط الاجتماعي

مؤشر متعدد الأبعاد من: إشباع احتياجات أساسية، تغير الدخل الحقيقي، البطالة، الاستقرار، الثقة، والفروق المحلية. الإضراب يستلزم إضافةً إلى الضغط الاجتماعي عناصر مثل وجود قطاع منظم ومطالب وحافز للمشاركة.

### 7.4 المال والموازنة

- تخزن الأموال بوحدة صحيحة صغرى (`integer minor units`) أو نوع Decimal مضبوط، وليس `number` عشريًا للمدفوعات الحساسة.
- كل تحويل بين جهتين يولّد خصمًا وإضافةً متناظرين في دفتر مبسّط.
- الدعم والضرائب والتحويلات يجب أن تغيّر أرصدة الجهات المعنية، لا مجرد إحصاء إجمالي.
- أي مصدر/مصرف خارجي للنقود أو الموارد يجب أن يظهر في تقرير مبرّر.

### 7.5 مقياس الواقعية

تُقاس الواقعية عبر **اتساق العلاقات واتجاهات الاستجابة** في سيناريوهات مرجعية، لا عن طريق الزعم بأن أسعار محاكاة خيالية تطابق بيانات اقتصاد حقيقي.

## 8. كتالوج السيناريوهات (Scenario Catalogue)

كل سيناريو يتضمن: حالة ابتدائية، تدخل/صدمة، سلوك متوقع **اتجاهيًا**، مقاييس رصد، وحالات فشل. لا ينبغي كتابة نتائج «فوز/خسارة» ثابتة مسبقًا.

### SC-01 — اقتصاد مستقر دون تدخل

- **Given:** مدن تنتج سلعًا مختلفة، مخزونات كافية، طرق مفتوحة، طلب ضمن القدرة الإنتاجية.
- **When:** تشغيل 180 يومًا افتراضيًا دون صدمات خارجية.
- **Then:** تستمر عمليات الإنتاج والتبادل والاستهلاك؛ لا تظهر مخزونات سالبة أو نقود غير مبررة، وتصبح مؤشرات الاقتصاد قابلة للقراءة.
- **القياس:** الإنتاج، الاستهلاك، متوسط الأسعار، التوظيف، ثبات الأرصدة.

### SC-02 — جفاف يضرب إقليمًا زراعيًا

- **Given:** اعتماد مدينتين على إنتاج الحبوب محليًا.
- **When:** تخفيض القدرة الزراعية 40% في منطقة لمدة 30 Tick.
- **Then:** ينخفض الإنتاج مقارنة بمسار مطابق دون جفاف؛ قد يرتفع سعر الحبوب أو تزيد الواردات أو ينخفض الاستهلاك وفق البدائل المتاحة.
- **القياس:** الإنتاج المحلي، أسعار الغذاء، الواردات، الحاجة غير المشبعة، رضا السكان.
- **مهم:** لا تُبرمج الإضرابات كنتيجة مباشرة للجفاف.

### SC-03 — استيراد غذاء من دولة مجاورة

- **Given:** فائض حبوب في الدولة B ونقص في الدولة A وطريق تجارة مفتوح.
- **When:** تسمح الحكومتان بالتجارة ويقرر التجار الاستيراد.
- **Then:** تُحجز البضائع عند الشحن، تُخصم تكاليف النقل، تصل بعد المدة المحددة، وتتاح بعدها في سوق الوجهة.
- **القياس:** عدد الشحنات، هامش الربح، زمن التسليم، أسعار المدينتين.

### SC-04 — إغلاق طريق تجاري رئيسي

- **Given:** عدة مدن تعتمد على طريق واحد لسلعة أساسية.
- **When:** إغلاق الطريق لعشرين يومًا.
- **Then:** تُمنع الشحنات الجديدة عبره، ويبحث الوكلاء عن بديل إن وجد؛ قد ترتفع تكاليف النقل ويتأخر التوريد.
- **القياس:** المسارات البديلة، تكلفة النقل، المخزون، التأخير.

### SC-05 — إضراب عمالي في قطاع التعدين

- **Given:** ارتفاع تكلفة المعيشة، ضعف الأجور الحقيقية، وجود تنظيم عمالي، ومطالب معلنة.
- **When:** لا تُلبّى المطالب وتتحقق قواعد قرار الإضراب.
- **Then:** تنخفض الطاقة الإنتاجية في المؤسسات المشاركة؛ ينشأ ضغط على الصناعات المعتمدة على الحديد/الفحم؛ قد تبدأ مفاوضات.
- **القياس:** مشاركة العمال، حجم الإنتاج المتعطل، خسائر الأجور والأرباح، مدة التفاوض.

### SC-06 — تفاوض ناجح بعد إضراب

- **Given:** إضراب نشط مع إمكانية تقديم تنازلات مالية أو تنظيمية.
- **When:** تقبل الأطراف تسوية وفق أهدافها وميزانياتها.
- **Then:** ينتقل الحدث إلى حالة `resolved`، وتعود القدرة الإنتاجية تدريجيًا وفق القواعد؛ تتغير الأجور أو ظروف العمل بحسب الاتفاق.
- **القياس:** تكلفة التسوية، الأجور، الثقة، العودة للإنتاج.

### SC-07 — دعم حكومي للغذاء

- **Given:** ارتفاع أسعار سلعة أساسية، حكومة لديها احتياطي مالي معلوم.
- **When:** إصدار سياسة دعم لمدة 60 يومًا.
- **Then:** تُسجل كلفة الدعم في الخزينة؛ قد يتحسن الوصول للسلعة، لكن يجب ألّا يستطيع الدعم خلق سلع مادية من العدم.
- **القياس:** كلفة السياسة، الاستهلاك، المخزون، الرضا، العجز.

### SC-08 — ضرائب مرتفعة وتباطؤ استثمار

- **Given:** منشآت لديها تكاليف وأرباح متفاوتة.
- **When:** ترفع الحكومة ضريبة محددة.
- **Then:** تتغير أرباح الشركات وإيرادات الخزينة؛ قد تقل الاستثمارات لدى بعض الوكلاء وفق معايير قراراتهم، لا بشكل حتمي عام.
- **القياس:** أرباح الشركات، الاستثمار، الإيرادات، التوظيف.

### SC-09 — اتفاقية تجارية بين دولتين

- **Given:** رسومات جمركية قائمة، ومساران تجاريان نشطان.
- **When:** توقيع اتفاقية تخفيض رسوم لسلع مختارة.
- **Then:** تتغير تكلفة الاستيراد للسلع المشمولة فقط، ويمكن للتجار تعديل قراراتهم.
- **القياس:** حجم التجارة، إيرادات الجمارك، الأسعار، الفائض التجاري.

### SC-10 — عقوبات دبلوماسية متبادلة

- **Given:** اعتماد متبادل على مواد خام أو بضائع مصنّعة.
- **When:** فرض قيود تجارية من دولة على أخرى ثم رد مماثل إذا اختارته الحكومة الثانية.
- **Then:** تعاد حسابات تكلفة التبادل وإتاحة المسارات والتوريد؛ قد يتضرر الطرفان بدرجات مختلفة.
- **القياس:** واردات وصادرات، أسعار، دخل قطاعات، الثقة الدبلوماسية.

### SC-11 — انتقال سياسي أو انتخابات

- **Given:** شكل حكومي يسمح بآلية انتقال محددة، وجماعات مصالح وسياسات متنافسة.
- **When:** يحين موعد الانتخابات أو تنفّذ آلية انتقال السلطة.
- **Then:** قد تتبدل الأولويات والضرائب والاتفاقيات ضمن القيود المؤسسية، دون افتراض نتيجة مسبقة.
- **القياس:** التغيير التشريعي، الثقة، الميزانية، تأثير السياسة بمرور الزمن.

### SC-12 — موجة هجرة من مدينة إلى أخرى

- **Given:** مدينة ذات بطالة مرتفعة وأخرى بها طلب عمل وأجور أعلى.
- **When:** تتوفر قدرة انتقال ويقرر بعض السكان الهجرة.
- **Then:** ينخفض عدد سكان المصدر بالقدر نفسه الذي يزيد به عدد سكان الوجهة (بعد احتساب الفقد/الوفيات إن فُعّلت)، وتتغير سوقا العمل والسكن/الاستهلاك.
- **القياس:** صافي الهجرة، الأجور، البطالة، الطلب.

### SC-13 — انهيار شركة مؤثرة

- **Given:** منشأة كبيرة تتكبد خسائر متواصلة وتملك مخزونًا والتزامات.
- **When:** تنفد السيولة أو تتحقق شروط التصفية المعرّفة.
- **Then:** تتوقف/تقل عمليات الإنتاج، يفقد بعض العاملين وظائفهم، ويؤثر توقفها في المشترين والموردين وفق اعتمادهم عليها.
- **القياس:** البطالة، المخزون، الأسعار، انتقال الأثر بين القطاعات.

### SC-14 — أزمة في ميزانية الحكومة

- **Given:** مصروفات دعم وخدمات تفوق الإيرادات مع خزينة محدودة.
- **When:** يستمر العجز مدة كافية.
- **Then:** تتبع الحكومة سياسة صريحة: خفض إنفاق أو رفع إيرادات أو اقتراض إذا كان مفعّلًا. لا يجوز أن تصبح الخزينة بلا حدود بسبب خطأ برمجي.
- **القياس:** أرصدة الخزينة، الخدمات، الاستقرار، ضرائب المستقبل.

### SC-15 — إعادة تشغيل التجربة نفسها

- **Given:** نسخة محرك ثابتة، Config واحد، seed واحد، وتسلسل أوامر مطابق.
- **When:** تشغيل محاكاتين مستقلتين كل منهما 1000 Tick.
- **Then:** تتطابق بصمة النتائج المحددة، بما فيها حالات الكيانات والأحداث والترتيب الحتمي.
- **القياس:** hash للحالة وللأحداث، عدد الأحداث، المقاييس النهائية.

### SC-16 — تجربة مقارنة سياسات (Counterfactual)

- **Given:** Snapshot عند Tick 200.
- **When:** اشتقاق تشغيل A بزيادة دعم الغذاء وتشغيل B دون زيادة، ثم 100 Tick إضافية لكل منهما.
- **Then:** يمكن مقارنة الأسعار والميزانية والرضا والآثار الجانبية من نقطة بداية متطابقة.
- **القياس:** تغير كل مؤشر نسبةً إلى خط الأساس، دون الادعاء بأن الفرق يثبت علاقة علمية خارج النموذج.

### SC-17 — اختبار الحالات الطرفية

- مدينة معزولة، مدينة دون عمالة، سوق دون عروض، خزانة صفر، مدينة دون سكان، موارد عند الحد الأقصى، شحنة لم يعد طريقها متاحًا، وسياسة منتهية.
- **القبول:** لا NaN ولا Infinity ولا أرصدة/مخزونات سالبة؛ وتوجد نتائج/أخطاء مجال واضحة.

## 10. الاختيارات التقنية المعتمدة مبدئيًا

| الطبقة | الأداة | سبب الاختيار | التوقيت |
|---|---|---|---|
| لغة | TypeScript (strict) | عقود قوية بين وحدات كثيرة | البداية |
| Runtime | Node.js | تشغيل مستقل وخدمات لاحقة | البداية |
| Monorepo | pnpm Workspaces | مشاركة الحزم وضبط التبعيات | البداية |
| اختبار المحرك | Vitest | وحدات وProperty/Scenario Tests | البداية |
| ضبط الكود | ESLint + Prettier | أسلوب موحد وتحذيرات مبكرة | البداية |
| CLI | Node.js CLI بسيط | تشغيل السيناريوات دون واجهة | البداية |
| التحقق | Zod | صحة ملفات العالم والأوامر | مبكرًا |
| Backend | Fastify | API لإدارة العوالم والتشغيل | بعد النواة |
| قاعدة بيانات | PostgreSQL | بيانات وصفية وسجل تجارب وSnapshots | بعد إثبات النواة |
| ORM / SQL | Drizzle ORM | نمذجة وتصريحات SQL قابلة للتتبع | عند إدخال DB |
| Frontend | React + Vite | تحكم وتصور منفصل عن المنطق | بعد API |
| تصميم الواجهة | Tailwind CSS + shadcn/ui | لوحات تحكم وأدوات تنظيمية | مع الواجهة |
| رسم الخرائط 2D | PixiJS | خريطة تفاعلية لمناطق ومدن ومسارات | مع الواجهة |
| رسوم بيانية | Apache ECharts | سلاسل زمنية ومقارنات | مع الواجهة |
| اتصال حي | WebSocket | تحديث المقاييس والحالة دون إعادة تحميل | عند الحاجة |
| E2E | Playwright | اختبار رحلات المستخدم | مع الواجهة |
| تشغيل | Docker Compose | بيئة محلية قابلة للإعادة | عند ظهور خدمات متعددة |
| CI | GitHub Actions | الاختبارات والـlint والبناء | مبكرًا |
| أداء متقدم | Node Worker Threads | توزيع أعمال حسابية بعد Profiling | عند الحاجة |
| تحسين لاحق محتمل | Rust / WebAssembly | تسريع أجزاء ضيقة بعد القياس | اختياري |

**قرارات سلبية واضحة:** لا Microservices، لا Kubernetes، لا Redis، لا LLM في كل Tick، ولا WebAssembly افتراضيًا. هذه الخيارات تُعاد مناقشتها فقط إذا ظهرت حاجة مقاسة.

الحزم هنا **حدود منطقية مقترحة** وليست التزامًا بإنشاء كل الحزم فورًا؛ يبدأ المشروع بعدد قليل ويُفصل عند ظهور تعقيد حقيقي.

### 10.2 واجهات الاتصال مبدئيًا

- `POST /worlds` إنشاء عالم.
- `GET /worlds/:id` بيانات وحالة مختصرة.
- `POST /worlds/:id/commands` أوامر تحقق وصلاحيات.
- `POST /worlds/:id/runs` تشغيل عدد Ticks وإعادة `runId` إذا كان التنفيذ طويلًا.
- `GET /worlds/:id/metrics?from=&to=` مؤشرات زمنية.
- `GET /worlds/:id/events?cursor=` سجل أحداث قابل للتصفح.
- `POST /worlds/:id/snapshots` نقطة حفظ.
- `GET /worlds/:id/snapshots` قائمة نقاط الحفظ.
- `GET /runs/:id` حالة تشغيل منفصل.
- WebSocket لاحقًا: بث **تغييرات مختصرة** أو مقاييس لا نسخ حالة العالم كاملةً كل Tick.

**متطلبات API:** تحقق Zod، ترقيم نسخ، Idempotency للأوامر الحساسة، إرجاع أخطاء مجال واضحة، وعدم استقبال أمرين متعارضين دون ترتيب محدد. تسجيل من غيّر حالة العالم ومتى (Audit).

## 11. التخزين، الأداء، والصحة الرياضية

### 11.1 حفظ الحالة

- **Snapshots** دورية للحالة الكاملة مع `engineVersion` و`rulesVersion` وSeed والـTick.
- **Event Log** يصف التحولات والأسباب المهمة؛ لا نفترض أنه وحده يكفي لإعادة بناء كل Tick ما لم نثبت ذلك.
- تخزين تكوين السيناريو منفصلًا عن حالة التشغيل.
- استخدام ضغط بيانات أو حفظ تفاضلي فقط بعد قياس الحجم والأداء.
- لا يسمح باستعادة Snapshot من نسخة غير متوافقة بصمت؛ يلزم تحويل نسخة أو خطأ مفهوم.

### 11.2 الأداء والتوسعة

- أولًا قياس زمن كل نظام في Tick والذاكرة وعدد الكيانات والصفقات.
- الإشارة إلى أهداف مرجعية للنسخة المتقدمة: **12 مدينة، 3 دول، 1000 Tick** دون تسرب ذاكرة أو انهيار.
- معيار سرعة رقمي **يُحدَّد بعد قياس الجهاز والـVertical Slice**، وليس افتراضًا غير مثبت الآن.
- استخدام عمليات مجمّعة وتجنب نسخ بيانات العالم بالكامل في كل دورة.
- Worker Threads اختيار لاحق؛ قد تؤدي إلى نتائج غير حتمية إن لم تضبط التجميع والـRNG.

### 11.3 Invariants إلزامية

1. الكميات المتاحة والمحجوزة غير سالبة.
2. ما انتقل من مخزون إلى شحنة لا يُحتسب مرة ثانية في مخزون المدينة.
3. كل دفعة نقدية أو ضريبية لها مصدر ووجهة أو عملية إصدار/إتلاف صريحة.
4. توزيع السكان بين المدن متسق مع المواليد/الوفيات/الهجرة المسجلة.
5. لا حالات `NaN` أو `Infinity` في المؤشرات أو الأسعار.
6. توازن المدخلات والمخرجات وفق وصفات الإنتاج المسجّلة.
7. الوحدات الزمنية والمحاسبية لا تُخلط صامتًا.
8. الأوامر غير الصالحة لا تترك تغييرات جزئية في العالم.
9. معرّفات الأحداث والكيانات فريدة ومستقرة.
10. القرار نفسه تحت المدخلات نفسها والـSeed نفسها يعطي النتيجة نفسها.

## 12. استراتيجية الاختبارات

| النوع | المثال | متى يُجرى؟ |
|---|---|---|
| Unit | وصفة لا تنتج دون خامات كافية | مع كل ميزة |
| Invariant/Property | لا تنخفض المخزونات تحت الصفر عبر آلاف حالات مولّدة | مع كل تغيير منطق محوري |
| Integration | إنتاج -> نقل -> سوق -> استهلاك | أسبوعيًا وعلى CI |
| Determinism | تشغيلان متماثلان -> بصمتان متطابقتان | على CI |
| Scenario Regression | الجفاف يؤثر في إنتاج الحبوب مقارنة بخط الأساس | على CI |
| Persistence | Snapshot/Restore ثم استكمال يطابق التشغيل المتواصل | عند إضافة التخزين |
| Performance | قياس تكلفة Tick مع 3/12/100 مدينة | قبل قرارات التحسين |
| API | أوامر متزامنة وتحقق وصلاحيات | عند API |
| E2E | إنشاء عالم وتشغيله ومراقبة أثر قرار حكومي | عند الواجهة |

**لا تكتفِ باختبار أن النتائج «تبدو معقولة».** اختبر حفظ الموارد والأموال والسكان والنتائج الاتجاهية، مع تسجيل نسخة السيناريو التي أنتجت أي baseline.

## 13. خارطة طريق تنفيذية مقترحة (20 أسبوعًا قابلة للتمديد)

### 13.1 بوابات قبول المراحل

- **Gate A:** محرك دون واجهة + Determinism + حفظ موارد.
- **Gate B:** سوق محلي متكامل + تقارير استهلاك/إنتاج/سعر.
- **Gate C:** تجارة بين مدن + رسوم + أزمنة شحن.
- **Gate D:** صدمة اقتصادية تنتج أثرًا سياسيًا **شرطيًا غير ثابت**.
- **Gate E:** حفظ واستعادة ومقارنة سيناريوهات من نفس الأساس.
- **Gate F:** واجهة تراقب العالم ولا تحتوي منطقًا اقتصاديًا حاسمًا.

لا تنتقل للمرحلة التالية إذا كانت invariants الرئيسية مكسورة؛ بدلاً من ذلك أصلح منطق العالم.

## 14. كيف نستخدم AI في التطوير

يمكن تقسيم مساعدي الذكاء الاصطناعي إلى أدوار **من دون** أن يحل أي منهم محل مراجعة صاحب المشروع:

- **Architect:** يقترح التصميم ويبرر المفاضلات ويسجل قرارات ADR.
- **Implementation:** يطبق مهمة محددة بعقد واختبارات واضحة.
- **QA/Scenario Reviewer:** يختبر الحالات الطرفية واتساق قواعد الاقتصاد والسياسة.
- **Performance Reviewer:** يقيس اختناقات الأداء بالأرقام قبل التوصية بتحسينات.

### قواعد عمل الوكلاء

1. قبل أي ميزة: تحديد المتطلب، العقود، اختبارات القبول، وتأثيرها في الأنظمة الأخرى.
2. ممنوع إضافة مكتبات أو خدمات جديدة لمجرد التفضيل الشخصي؛ يلزم تبرير بسيط.
3. ممنوع إخفاء مشاكل منطقية بمحاكاة أحداث جاهزة أو قيم ثابتة لا علاقة لها بالمدخلات.
4. كل تغيير في Tick order أو RNG أو الحسابات المالية يتطلب اختبارات Determinism/Regression.
5. لا يتم دمج تغييرات كبيرة دون مراجعة وفهم آثارها.
6. كل قرار غير محسوم يُكتب في `docs/adr/` ولا يُعامل كأنه حُسم مسبقًا.

## 16. أمثلة لبيانات عالم تجريبي

**السيناريو المرجعي `three-nations-trade-and-politics`:** عالم خيالي، لا يمثل دولًا حقيقية.

| الدولة | الاقتصاد الأولي | التحدي البنيوي | العلاقة المبدئية |
|---|---|---|---|
| دولة السهول | حبوب وزراعة وغذاء | نقص المعدات الصناعية | تصدّر الغذاء إلى الجبال |
| دولة الجبال | فحم وحديد وأدوات | نقص الغذاء | تحتاج استيراد الحبوب |
| دولة السواحل | تجارة ونسيج ونقل | اعتماد على طرق بحرية/برية | وسيط تجاري بين الدولتين |

- لكل دولة أربع مدن، مع اختلاف القدرة الإنتاجية والسكان والطرق.
- عند بدء التشغيل، توجد تجارة محدودة وتسويات مالية معقولة.
- بعد 120 Tick يمكن إدخال الجفاف أو إغلاق المعبر أو قرار فرض رسوم، ثم مقارنة التأثيرات.
- أسماء الدول ومواصفات البداية كلها Config وليست مرمزة داخل النواة.

### مثال تخيلي لمخرجات تقرير

```text
World: three-nations-trade-and-politics
Seed: 42 | Tick: 300 | Rules: v0.1

Food supply index: ...
Average grain price by city: ...
Unemployment by city: ...
Active strikes: ...
Government treasury by nation: ...
Active trade agreements: ...
Largest supply-chain bottleneck: ...
```

قيم المؤشرات تُحسب أثناء التنفيذ؛ لا توضع أرقام وهمية مسبقًا في التقارير.

## 17. سجل القرارات والأسئلة المفتوحة

### 17.1 قرارات معتمدة في هذه المسودة

- الاقتصاد هو القلب، والحضارات والسياسة والدبلوماسية أنظمة تؤثر فيه وتتأثر به.
- المشروع **محرك محاكاة قبل أن يكون لعبة**.
- TypeScript وNode.js أساس التنفيذ.
- النواة تعمل بلا واجهة ولا قاعدة بيانات إجبارية.
- محاكاة مجموعات سكانية بدل كل فرد في المراحل الأولى.
- المدن والدول المتعددة والتجارة والاحتجاجات والإضرابات عناصر أساسية في الرؤية.
- واجهة React ورسوم PixiJS ومقاييس ECharts تأتي بعد المحرك.
- Modular Monolith بدل الخدمات المصغرة في البداية.

### 17.2 قرارات **لم تُحسم بعد** ويجب أن تُناقش قبل تثبيت تفاصيلها

1. **الفترة الزمنية للعالم:** ما قبل الصناعة، صناعية، حديثة، أم قواعد مرنة حسب السيناريو؟
2. **درجة الواقعية الاقتصادية:** نظام أسعار مبسط أم سوق عروض وطلبات ومعاملات مالية أكثر تفصيلًا؟
3. **النظام النقدي:** عملة واحدة للعالم في VS أم عملة لكل دولة وأسعار صرف؟
4. **تمثيل الشركات:** شركة لكل منشأة أم منتجون مجمّعون حسب القطاع والمدينة؟
5. **تمثيل السكان:** كم فئة في كل مدينة، وكيف تُحدَّث المهارات والطبقات؟
6. **القرار الحكومي:** قواعد قرار تلقائية فقط أم تدخل يدوي مباشر من المستخدم أثناء التشغيل؟
7. **شكل الخريطة:** شبكة مدن وعقد تجارية أولًا أم حدود جغرافية مرسومة مبكرًا؟
8. **السياسة:** مدى تفصيل الأحزاب والانتخابات والسلطات التشريعية والقضائية في M1؟
9. **الدبلوماسية:** هل توجد موارد استراتيجية وحظر صادرات متعدد الأطراف في M1؟
10. **معايير الأداء المستهدفة:** تُحدد بعد قياس نموذج العمل على الجهاز الفعلي.

### 17.3 سياسة تغيير المواصفات

أي قرار جديد يدوّن بتاريخه، وسبب اختياره، والبدائل المرفوضة، وتأثيره في الاختبارات والواجهات. يتغير رقم النسخة عند تعديل جوهري في قواعد الاقتصاد أو السياسة أو نموذج البيانات.
