# EPCSE — عقود تقنية مقترحة

**الحالة: تخطيط، لم يُعتمد أو يُنفّذ.** هذه العقود تحدد الأسئلة والاختبارات وليست ترخيصًا بحسم خيارات المنتج المفتوحة في [سجل القرارات](decisions.md). المرجع: [المواصفة الأصلية](reference/original-spec-ar.md). تكامل الأنظمة والمهام في [المعمارية](architecture.md) و[المهام](tasks.md).

## تشغيل ووقت وأوامر

- يقترح المحرك `create(config, seed)` و`submit(command)` و`step()` و`run(n)` و`snapshot()` و`restore(snapshot)` مع حدود قراءة لا تسمح بالتعديل الخفي؛ التوقيع النهائي قابل للنقاش. tick افتراضي يوم؛ السرعة الخارجية لا تغيّر القواعد.
- الأوامر تملك معرّفًا وترتيبًا حتميًا وحدّ تطبيق معلومًا؛ لا تتوقف الأوامر على وقت النظام. التحقق من الصلاحية والموارد والتعارض يسبق التحويل أو تُطبّق المعاملة على نسخة مؤقتة؛ أمر مرفوض لا يترك كتابة جزئية ولا استهلاك RNG خفيًا. عرّف نتيجة قبول/رفض وأثر الترتيب واختبره.
- ترتيب مراحل §5.2 في المرجع مقترح قابل للتعديل باختبارات: الوارد يصل قبل السوق؛ المغادر يصل في tick لاحق. تثبيت الإصدار والترتيب شرط المقارنة؛ كل تغيير يستدعي regression.

## العشوائية والتكرار والبصمة

- خزّن seed، معرف وخوارزمية وإصدار مولد الأرقام وحالته لكل stream؛ اشتق streams من معرّفات ثابتة لا ترتيب اكتشاف الكيانات. لا `Math.random()` أو ساعة نظام داخل انتقال الحالة؛ فرز ثابت مع كسر التعادل بمعرّف ثابت. تجنب إدخال قياسات الأداء ضمن الحالة الحتمية.
- canonical serialization تحدد ترتيب المفاتيح والعناصر، الترميز، وتمثيل القيم والأعداد وغياب `undefined`؛ تشمل الحالة المؤثرة والمجدول والأوامر وحالة RNG والنسخ. بصمة الحالة وسجل الأحداث منفصلتان ولديهما تعريف نسخة وخوارزمية مثبتان. التكرار مضمون ضمن بيئة/إصدارات مدعومة موثقة فقط حتى تثبت اختبارات البيئات الأوسع؛ تعامل صراحة مع اختلاف floating point.
- اختبارات: تشغيلان 1000 tick مع أوامر متطابقة وحساب بصمتين؛ حالات تعادل وترتيب إدراج مختلف؛ snapshot عند 200 ثم استكمال ومقارنة تشغيل متواصل؛ عند تغيير نسخة قواعد قد تختلف البصمة بشكل مشروع.

## النقود والكميات والدفاتر

- النقود بوحدة صحيحة صغرى؛ الكميات بوحدات صحيحة مضبوطة المقياس أو نوع decimal محدد، مع مقياس ووحدة لكل سلعة. نوع الحساب الدقيق وحدوده وserialization مقترحات تحتاج ADR، و`number` لا يكفي دون فحص `Number.isSafeInteger` لجميع المدخلات والنتائج الوسيطة. ارفض overflow وNaN وInfinity بدل التقريب الصامت؛ حدد rounding واتجاهه وبواقيه.
- كل دفعة تسجل مصدرًا ووجهة ومبلغًا ووحدة؛ إصدار/إتلاف صريحان فقط. دعم وتمويل ونقل وضرائب لها طرف يدفع وآخر يقبض؛ الخزينة لا تُستكمل تلقائيًا. لا يفترض دفتر متوازن ثبات توزيع الأرصدة.
- المخزون المملوك والمتاح والمحجوز والشحنات في الطريق تمثل حالات غير مزدوجة؛ حجز/إرسال/وصول انتقالات ذرية. الإنتاج يسجل مدخلات مخصومة ومخرجات حسب وصفة ومعاملات وحدات، لا يدّعي تساوي عدد وحدات سلع مختلفة. التلف والاستهلاك والتحويلات مصادر/مصارف مسجلة؛ الهجرة تحفظ إجمالي السكان إلا ولادة/وفاة مبررة.
- اختبارات عقود: حدود صفر وقيم قصوى وoverflow؛ تحويل فاشل دون تغير؛ حجز وشحن ووصول دون ازدواج؛ دفع متناظر؛ وصفة عاجزة عن الإنتاج عند نفاد مدخل؛ إغلاق الطريق بعد الإرسال وفق سياسة معلنة لا مفترضة.

## أحداث ومقاييس ولقطات

- حدث يحدد ID ثابتًا وtick ونوعًا وكيانات وسببًا وآثارًا ووحدات وإصدار مخطط؛ توثّق السياسة التي تحدد ما يُسجّل. لا تفترض أن event log يعيد كل حالة؛ command log واللقطات لهما عقود منفصلة. حافظ على ترتيب محدد وأسباب قابلة للتتبع.
- snapshot كاملة متسقة عند حد دورة، تشمل العالم والإعدادات والقواعد والمحرك وseed وحالات RNG والجدولة والأوامر اللازمة؛ الاستعادة الذرية ترفض نسخة غير متوافقة بخطأ واضح أو تحويل معتمد. الحفظ في الذاكرة مبكرًا لا يعني تشغيل PostgreSQL؛ تخزين دائم adapter لاحق.
- السلاسل الزمنية تربط المقياس بكيان ووحدة وtick؛ مقارنة السيناريوهين من نسخة واحدة تختلف فقط بالأوامر المقصودة. اختبارات SC-15 وSC-16 وrestore، واستقرار ترتيب الأحداث والأخطاء وإصدارات التهيئة.

## حدود API والواجهة والأمان

- API مستقبلية تتحقق من الأوامر عبر schema وعقود أخطاء وصلاحيات وترتيب التعارض وidempotency؛ النواة تعيد التحقق من invariants. تدقيق من غيّر ماذا ومتى يأتي من طبقة التشغيل، لا يدخل ساعة النظام في حالة المحاكاة.
- الواجهة تقرأ projections وترسل أوامر، ولا تغير الحالة مباشرة أو تحتوي قرارًا اقتصاديًا حاسمًا. حفظ/شبكة/ساعة تشغيل وبيانات اعتماد خارج النواة. التحقق التكاملـي لاحقًا يستخدم بيانات اصطناعية، ولا يدّعي ضمانًا أمنيًا قبل اختبار فعلي.

هذه أمثلة عقود قابلة للنقاش وليست نتائج تشغيل. راجع المصدر في أي تعارض، واكتب قرارًا واختبارًا قبل تثبيت التفاصيل.
